# ビーチバレー ゲーム仕様（プロトタイプ）

イメージ: [`reference/concept-beach.webp`](reference/concept-beach.webp)

## 基本
- スマホ横持ち・Webブラウザ（GitHub Pages）
- 2対2。操作するのは自分（A1）だけ。味方（A2）・相手（B1, B2）はbot
- 見た目は3D（Three.js, `src/render/three3d.ts`）、ゲームとしては横から見た2D（x = コート長手方向, y = 高さ, 選手の `z` は描画用の奥行き）
  - `?view=2d` で依存なしの2D表示（`src/render/canvas2d.ts`）。WebGL2 が使えない時も2D
  - 画質: `?quality=high|low`。未指定なら high で始め、FPSが低ければ low に落とす（high = 影2048・MSAA・ブルーム・被写界深度）

## 3D素材（`assets/`）
- 方針: 素材で作れる部分は素材を使い、自作しない
- 使用中: Kenney Nature Kit（CC0, ヤシ・岩・草）、three.js の `waternormals.jpg`（MIT, 海）
- 空: Poly Haven `kloofendal_48d_partly_cloudy_puresky`（CC0）。砂: Poly Haven `sand_03`、波打ち際の濡れた砂: `damp_beach_sand`（CC0）。`node tools/fetch-assets.mjs`（`--only sky|sand|wetSand`、`--id` で別素材を試せる）で取得し `assets/manifest.json` に記録
- 素材候補の比較は、サムネイルではなく実際のテクスチャ（色・法線）を取得して見る（cdn.polyhaven.com は許可外）
- ambientCG はAPI（ambientcg.com）には届くが、ファイル配信元 `acg-media.struffelproductions.com` / `acg-download.struffelproductions.com` が未許可
- キャラは未定（カプセルで仮置き）。Kenney Mini Characters は頭身・雰囲気が参考画像と違いすぎるため不採用
- Kenney Nature Kit はローポリ・独特の配色（オレンジの幹・水色の葉）で参考画像に合わない。差し替えるまでの仮置き。glbの色がsRGB値のまま・金属度1で入っているので読み込み時に補正している（`src/render/scene/props.ts`）
- Quaternius の素材は itch.io / Google ドライブ経由のダウンロードなので、そのドメインの許可も必要

## 背景づくりの進め方
- まず参考画像を構図ごと再現して品質を詰め、品質が届いたらゲームのカメラに移す（素材・光・色は流用、配置だけやり直す）
- `?scene=ref`: 参考画像のカメラ（コートの線とポールから逆算。位置 (-0.64, 1.72, 12.89)、左へ約8°、縦画角約30°）で、ゲームは止めて表示する。遠景・小物は単色の仮の形（ブロックアウト）で、参考画像の画素位置と距離から配置している（`src/render/scene/ref-shot.ts`）
- 参考画像はAI生成なので遠近が厳密には合わない。線は10〜20pxずれる。水平線の高さを優先して合わせた
- 比較: `node tools/ref-compare.mjs` → `.ref-compare/`（render / side / overlay / gray / stats.json）。空・海・砂・島の領域ごとに参考画像との色の数値（平均・明暗の幅・暗い10%/明るい10%の色）と、砂の上の影の明るさ比（参考 0.78）を表示する
- 見た目の調整値は `src/render/look.ts`（`?look=KEY:VAL,...`、`ref-compare --look` で上書き）
- 方針（ユーザーと合意）: **海と砂浜を先に高品質にする**。それができれば、あとは素材を置けば求める品質になる

### 済んだこと
- 構図: `?scene=ref` と比較ツール
- 空: HDRIを空の球に表示し、彩度・天頂の暗さを調整できる（`SKY_SAT` / `SKY_ZENITH`。**初期値は未調整**）。照明用のHDRIは太陽の部分を抑え、影は DirectionalLight で出す（実写HDRIは太陽が写っていて、そのままだと影が消える）
- 太陽の向き: 参考画像のポールの影から測った（右奥、高さ約51°）。光の強さは、砂の上の影が日なたの約0.8倍になるよう合わせた
- かすみ: 陸地だけにかかる上限付きのフォグ（`FOG_*`、初期値は無効）
- 砂（`src/render/scene/beach.ts`）: グラデーションマップ（テクスチャの明暗 → `SAND_DARK` オレンジ〜`SAND_LIGHT` 黄色、`SAND_GAMMA` でカーブ）。AOでくぼみを暗く、大きな縮尺のコピーで繰り返しを隠す。参考画像と数値でほぼ一致（平均 241,214,170 対 247,216,174）
- 浜の断面（`sandHeight` / `SAND_HEIGHT_GLSL` / `WATERLINE_Z`）は海と共通で使う。波打ち際の濡れた砂の帯（`setWetReach`）は海の寄せ波で動かす想定

### 残っている課題
- 砂: 参考画像は細かいへこみが均一に散らばるが、今は大きめのオレンジのまだらが目立つ。凹凸の密度も足りない。視差と自己影の処理（`SAND_HEIGHT`）は入っているが、この素材では効果が薄く無効
- 空の色の調整（初期値）、かすみの初期値、明るい所がトーンマッピングで頭打ちになる点は、最後の色合わせ（LUT）でまとめて扱う
- ポールの色・太さ、岬・島・ヤシは素材に差し替える前提なので合わせていない

### 次: 海（計画）
参考画像の海の分解（奥から手前）:
1. 沖: 濃い青、遠近で潰れた細かい横長の波模様
2. 中ほど: ターコイズへのグラデーション、岸と平行なうねりの帯
3. 砕ける波: 光が透けた青緑の面と白い波頭（いちばん目立つ）
4. 波打ち際: 砂の上に広がるレース状の白い泡
5. 太陽側のきらめき（ぼけた光の粒）、全体に被写界深度のぼけ

作り方（調べた手法。今の three の `Water` を自作シェーダーに置き換える）:
- 水深は浜の断面から計算できる（深度テクスチャ不要）。色は深さによる色ごとの吸収（Beer-Lambert）で、浅い所＝砂が透けたターコイズ、深い所＝濃い青
- 空の映り込みは鏡（シーンの描き直し）をやめ、HDRIからフレネルで取る（スマホの負荷が下がる）
- 細かい波は法線マップを大きさ違いで3層重ねて繰り返しを消す（`waternormals.jpg` を流用）
- 砕ける波は岸と平行な帯状のメッシュで、寄せて砕けて広がるループアニメーション（物理計算はしない）
- 泡の帯と濡れた砂は「岸からの距離」で決め、ノイズで崩す。泡のテクスチャはCC0素材を探す（未発見。見つからなければユーザーに相談）

## 現状と既知の問題（2026-10 時点）
- 3D表示は実機で元の操作どおり遊べることを確認済み
- `npm run e2e`（3D）は15項目中1項目「flick receives the ball」が失敗する。ヘッドレスのソフトウェアWebGLではフレームが遅く、テストのタッチ送信がボールに間に合わないため（2D表示では全項目成功、実機では問題なし）。テスト側の待ち方を直す必要がある
- ヘッドレス環境では描画速度が不安定（特に影）なので、その環境のFPSを基準に本番の画質を調整しない

## 操作
画面を3つの領域に分け、入力が競合しないようにしている（最初の1点が終わるまで点線とラベルで案内）。

| 領域 | 操作 | 動作 |
|---|---|---|
| 画面上部（スコアの少し下まで、`JUMP_ZONE_RATIO`） | タップ | ジャンプ（触れた瞬間） |
| 左半分（自陣側） | タッチ／ドラッグ | 指の位置へ走る（触れた瞬間から追従） |
| 右半分（相手側） | フリック | ボールを打つ（約10フレーム先行入力OK）。ボールが無くても素振りする |

フリックの方向:
- **上**: トス／パス（ネット寄りの自陣へ上げる）。3打目なら相手コートへ山なりで返す
- **前（ネット方向）**: 相手コートへ打つ。ジャンプ中でボールがネットより高ければ**スパイク**
- **後ろ**: 自陣の後方へパス
- 強さ（速さ）で狙う深さが変わる

サーブ: 自分がサーバーの時に右半分で前へフリック。

## ルール
- ラリーポイント制、15点先取（2点差が必要）
- 1チーム3タッチまで、同じ選手の連続タッチ不可（3打目は自動で相手コートへ）
- コート内に落ちたら落ちた側の失点、アウトは最後に触ったチームの失点
- 得点したチームが次のサーブ。サーブ権が移るたびにチーム内でサーバー交代

## bot
- 弾道を予測して担当者を決め、1打目パス → 2打目トス → 3打目アタック（ネット際ならジャンプスパイク）
- 相手の空いている所を狙う
- 反応の遅れ・狙いの誤差・移動速度で難易度を調整（`src/sim/world.ts` の `DEFAULT_TEAMMATE` / `DEFAULT_OPPONENTS`）
- 速い球（約10m/s超）はレシーブ失敗（空振り／弾く）しやすい

## 主要パラメータ
- 固定値（コート寸法、ネット高 2.24m、リーチなど）: `src/sim/constants.ts`
- 操作感の調整値（走る速さ、ジャンプ、最高点での滞空、打球の滞空時間、フリック判定など）: `src/sim/params.ts`
  - URLに `?tune=1` を付けると⚙ボタンからスライダーで変更できる（その端末に保存）
  - 「コピー」で変更した値のJSONをコピー → 開発側で `DEFAULT_PARAMS` に反映する
  - ヘッドレスでは `node tools/sim-cli.ts --autoplay --param T_SET=2.5`

ジャンプは最高点で `JUMP_HANG_FRAMES` フレーム止まる（スパイクのタイミングを取りやすくするため）。
