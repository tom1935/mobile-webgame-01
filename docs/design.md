# ビーチバレー ゲーム仕様（プロトタイプ）

イメージ: [`reference/concept-beach.webp`](reference/concept-beach.webp)

## 基本
- スマホ横持ち・Webブラウザ（GitHub Pages）
- 2対2。操作するのは自分（A1）だけ。味方（A2）・相手（B1, B2）はbot
- 見た目は3D（Three.js, `src/render/three3d.ts`）、ゲームとしては横から見た2D（x = コート長手方向, y = 高さ, 選手の `z` は描画用の奥行き）
  - `?view=2d` で依存なしの2D表示（`src/render/canvas2d.ts`）。WebGL2 が使えない時も2D
  - 画質: `?quality=high|low`。未指定なら high で始め、FPSが低ければ low に落とす（high = 影2048・MSAA・ブルーム・被写界深度）

## 3D素材（`assets/`）
- 方針: 素材で作れる部分は素材を使い、自作しない
- 使用中: Kenney Nature Kit（CC0, ヤシ・岩・草）、three.js の `waternormals.jpg`（MIT, 海）
- 未取得（仮置き中）: 空のHDRI・砂のPBRテクスチャ（Poly Haven / ambientCG, CC0）。`node tools/fetch-assets.mjs` で取得して `assets/manifest.json` に記録すると自動で使われる（要ネットワーク許可: api.polyhaven.com, dl.polyhaven.org, ambientcg.com）。未取得の間は空=three の Sky シェーダー、砂=単色
- キャラは未定（カプセルで仮置き）。Kenney Mini Characters は頭身・雰囲気が参考画像と違いすぎるため不採用
- Kenney Nature Kit はローポリ・独特の配色（オレンジの幹・水色の葉）で参考画像に合わない。差し替えるまでの仮置き。glbの色がsRGB値のまま・金属度1で入っているので読み込み時に補正している（`src/render/scene/props.ts`）
- Quaternius の素材は itch.io / Google ドライブ経由のダウンロードなので、そのドメインの許可も必要

## 現状と既知の問題（2026-10 時点）
- 3D表示は実機で元の操作どおり遊べることを確認済み
- `npm run e2e`（3D）は15項目中1項目「flick receives the ball」が失敗する。ヘッドレスのソフトウェアWebGLではフレームが遅く、テストのタッチ送信がボールに間に合わないため（2D表示では全項目成功、実機では問題なし）。テスト側の待ち方を直す必要がある
- ヘッドレス環境では描画速度が不安定（特に影）なので、その環境のFPSを基準に本番の画質を調整しない

## 操作
画面を3つの領域に分け、入力が競合しないようにしている（最初の1点が終わるまで点線とラベルで案内）。

| 領域 | 操作 | 動作 |
|---|---|---|
| 画面上部（スコアの少し下まで、`JUMP_ZONE_RATIO`） | タップ | ジャンプ（触れた瞬間） |
| 左半分（自陣側） | タッチ／ドラッグ | 指の位置へ走る（触れた瞬間から追従） |
| 右半分（相手側） | フリック | ボールを打つ（約10フレーム先行入力OK）。ボールが無くても素振りする |

フリックの方向:
- **上**: トス／パス（ネット寄りの自陣へ上げる）。3打目なら相手コートへ山なりで返す
- **前（ネット方向）**: 相手コートへ打つ。ジャンプ中でボールがネットより高ければ**スパイク**
- **後ろ**: 自陣の後方へパス
- 強さ（速さ）で狙う深さが変わる

サーブ: 自分がサーバーの時に右半分で前へフリック。

## ルール
- ラリーポイント制、15点先取（2点差が必要）
- 1チーム3タッチまで、同じ選手の連続タッチ不可（3打目は自動で相手コートへ）
- コート内に落ちたら落ちた側の失点、アウトは最後に触ったチームの失点
- 得点したチームが次のサーブ。サーブ権が移るたびにチーム内でサーバー交代

## bot
- 弾道を予測して担当者を決め、1打目パス → 2打目トス → 3打目アタック（ネット際ならジャンプスパイク）
- 相手の空いている所を狙う
- 反応の遅れ・狙いの誤差・移動速度で難易度を調整（`src/sim/world.ts` の `DEFAULT_TEAMMATE` / `DEFAULT_OPPONENTS`）
- 速い球（約10m/s超）はレシーブ失敗（空振り／弾く）しやすい

## 主要パラメータ
- 固定値（コート寸法、ネット高 2.24m、リーチなど）: `src/sim/constants.ts`
- 操作感の調整値（走る速さ、ジャンプ、最高点での滞空、打球の滞空時間、フリック判定など）: `src/sim/params.ts`
  - URLに `?tune=1` を付けると⚙ボタンからスライダーで変更できる（その端末に保存）
  - 「コピー」で変更した値のJSONをコピー → 開発側で `DEFAULT_PARAMS` に反映する
  - ヘッドレスでは `node tools/sim-cli.ts --autoplay --param T_SET=2.5`

ジャンプは最高点で `JUMP_HANG_FRAMES` フレーム止まる（スパイクのタイミングを取りやすくするため）。
